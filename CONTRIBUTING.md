# Contributing

Thank you for contributing.

1. Check the repository's README, license, security policy, and existing issues.
2. Open an issue before substantial product or architecture work.
3. Create a focused branch from the default branch.
4. Keep changes small, tested, and documented.
5. Never commit credentials, private user data, proprietary customer information, or unlicensed assets.
6. Open a pull request describing the problem, approach, validation, risk, and screenshots for UI changes.

Project-specific contribution instructions override this default. Security reports must use the private process described by the target repository's `SECURITY.md`.
