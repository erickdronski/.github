# Security policy

Do not publish credentials, private user data, vulnerability details, or working exploit instructions in a public issue.

For repositories with private vulnerability reporting enabled, use the repository's **Security** page and select **Report a vulnerability**. Otherwise, use a private contact route from [`@erickdronski`](https://github.com/erickdronski)'s profile and identify the affected repository.

Include the affected component, impact, reproduction steps, and suggested mitigation when known. Supported versions and response expectations may differ by repository; the current default branch and current release candidate are normally the priority.
